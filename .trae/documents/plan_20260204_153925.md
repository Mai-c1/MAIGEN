# MAIGEN-analysis 模块最终优化方案

既然您决定**彻底抛弃旧版 Prompt**，我们将全面拥抱 **“智能分流 + 自动闭环”** 的设计。这意味着我们将构建一个强规范的 AI 协作环境。

## 1. 核心代码改造 (`AiAnalysisService.java`)

### 1.1 智能分流与变量注册 (Smart Parsing)

系统将强制执行“Code/Text 分离”策略，不再向后兼容。

* **Step 执行后**：

  1. **Regex 提取**：提取所有 ` ``` ` 代码块内容 -> 存入 `{step_N_code}`。
  2. **文本清洗**：剔除代码块，保留自然语言 -> 存入 `{step_N_text}`。

* **Context 变量**：

  * `{step_N_code}`：**纯代码**（给编译器/审计员看）。

  * `{step_N_text}`：**纯思路**（给分析师看）。

  * （移除 `{step_N_output}`，不再支持混合输出）。

### 1.2 自动反馈闭环 (Auto-Feedback Loop)

* **审计检测**：检查最后一步（审计步）的 `{step_N_text}` 是否包含 `[FAIL]` 标记。

* **回滚注入**：

  * 若失败，取出 `{step_N_text}` 作为“审计意见”。

  * 回滚到 **生成步**。

  * **强制追加**：`\n\n【系统指令】上一步代码审计未通过，请根据以下意见修改：\n` + 审计意见。

* **重试限制**：最大 3 次，超过则抛出异常。

### 1.3 状态更新

* 细化状态流转：`ANALYZING` (20%) -> `GENERATING` (40%-50%) -> `VERIFYING` (70%)。

## 2. 配套 Prompt 用例 (Standardized Prompts)

代码改造完成后，您可以在数据库中配置以下 3 个标准步骤，测试这套全新的工作流：

### Step 1: 深度分析 (Role: System Architect)

* **System Prompt**:

  > 你是一个资深算法架构师。请分析用户给出的算法题目，输出解题思路、时间复杂度分析和伪代码。不要写具体的 Java 代码。

* **User Prompt**:

  > 题目描述：
  > {problem\_description}
  >
  > 限制条件：
  > 时间限制：{time\_limit}
  > 空间限制：{memory\_limit}

### Step 2: 代码生成 (Role: Senior Developer)

* **System Prompt**:

  > 你是一个高级 Java 开发工程师。请根据架构师的思路编写高质量的 Java 代码。
  > 必须使用 `public class Main`。
  > 必须包含 `public static void main(String[] args)`。
  > 只输出 Java 代码块，不要废话。

* **User Prompt**:

  > 请根据以下架构师的思路实现代码：
  > {step\_1\_text}
  >
  > 标准代码（仅供参考）：
  > {standard\_code}

### Step 3: 代码审计 (Role: Code Auditor)

* **System Prompt**:

  > 你是一个严格的代码审计员。请检查代码是否符合规范。
  > 如果代码有严重逻辑错误或不符合 Java 语法，请输出 `[FAIL]` 并给出修改建议。
  > 如果代码通过，请输出 `[PASS]`。

* **User Prompt**:

  > 请审计以下代码：
  > {step\_2\_code}

## 3. 实施与验证步骤

1. **代码实现**: 修改 `AiAnalysisService.java` 实现上述逻辑。
2. **Prompt 测试**: 您使用上述 Prompt 在系统上线后进行测试。
3. **结果验证**: 观察 `{step_2_code}` 是否纯净，以及 `{step_3_text}` 包含 `[FAIL]` 时是否触发重试。
