# 修复任务日志排序问题

## 目标

修复 `/task/detail` 接口返回的任务日志顺序问题。目前日志是按照 `stepOrder` (步骤序号) 排序的，导致在发生重试或循环执行时，日志无法按时间顺序正确展示（例如：步骤2的第二次执行记录会出现在步骤3的第一次执行记录之前）。

## 计划变更

**文件**: `d:\web\MAIGEN2\backend\MAIGEN-api\src\main\java\com\maigen\api\service\impl\TaskServiceImpl.java`

1. **修改** **`getTaskLogs`** **方法**:

   * 将查询条件中的 `.orderByAsc(TaskExecutionLog::getStepOrder)` 修改为 `.orderByAsc(TaskExecutionLog::getId)`。

   * 使用 `id` (自增主键) 排序可以确保严格的插入顺序，从而反映真实的执行时间线。

## 代码预览

```java
// 修改前
return taskExecutionLogService.lambdaQuery()
        .eq(TaskExecutionLog::getTaskId, taskId)
        .orderByAsc(TaskExecutionLog::getStepOrder) // 按步骤排序
        .list();

// 修改后
return taskExecutionLogService.lambdaQuery()
        .eq(TaskExecutionLog::getTaskId, taskId)
        .orderByAsc(TaskExecutionLog::getId) // 按插入时间排序
        .list();
```
