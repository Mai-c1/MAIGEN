# Analysis 模块重构：最终实施方案

根据我们的沟通，以下是最终确认的开发计划。我将立即开始执行。

## 1. 数据库变更 (MAIGEN-api)
*   **修改 `task` 表**:
    *   新增字段: `workflow_id` (BIGINT) - 关联生成方案。
    *   清理旧字段: 删除 `strategy` 相关字段。
*   **新增 `ai_workflow` 表**:
    *   `id`, `name`, `description`
    *   `is_visible` (BOOLEAN) - 控制前端可见性。
*   **新增 `ai_workflow_step` 表**:
    *   `workflow_id`, `step_order`
    *   `role_name`, `system_prompt`, `user_prompt_template`
*   **新增 `task_execution_log` 表**:
    *   `task_id`, `step_order`, `role_name`, `prompt_snapshot`, `ai_response`

## 2. API 接口开发
*   **管理端**: 方案与步骤的 CRUD、复制、可见性设置。
*   **用户端**:
    *   `GET /task/workflows`: 获取可见方案。
    *   `POST /task/submit`: 接收并处理 `workflowId`。
*   **缓存同步**: 配置变更时刷新 Redis `sys:ai:workflows`。

## 3. 执行引擎 (MAIGEN-analysis)
*   **多 Agent 协同**: 根据 `workflowId` 从 Redis 加载步骤，顺序执行。
*   **上下文传递**: 维护 `AnalysisContext`，支持 Prompt 变量替换。
*   **全链路日志**: 每一步执行结果通过 MQ (`QUEUE_TASK_LOG`) 异步回传至 API 模块入库。
