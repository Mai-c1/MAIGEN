## 前端签到功能对接与优化方案

### 1. API 接口完善
- **文件**: `frontend/src/api/points.ts`
- **操作**: 新增 `getMonthSignInDays()` 接口函数，对接后端 `GET /points/sign-in/month`。

### 2. 仪表盘数据真实化 (Dashboard)
- **文件**: `frontend/src/views/dashboard/index.vue`
- **逻辑改进**:
  - **初始状态**: 页面挂载时调用 `getMonthSignInDays`，根据返回的日期数组判断今日是否已签到，准确设置 `hasSignedIn`。
  - **热力图**: 弃用 `Math.random()` 模拟数据，使用真实的本月签到日期数组渲染 ECharts 日历热力图。
  - **统计信息**: 将“连续签到天数”展示改为“本月累计签到天数”，直接取日期数组的长度。

### 3. UI 表现调整
- **去周期化**: 
  - 修改 7 天进度条，将第 7 天的“礼盒”图标更换为标准的 `+5` 积分标识，匹配后端简化的奖励逻辑。
  - 修改签到成功后的 Message 提示，直接显示后端返回的消息。
- **状态联动**: 
  - 签到成功后，直接从返回的 `SignInResultVO` 中提取 `totalPoints` 并更新本地余额，不再进行前端手动计算。

### 4. 验证要点
- 验证进入页面时，若今日已签到，按钮是否正确显示为“已打卡”状态。
- 验证热力图是否准确反映了数据库中的签到记录。
- 验证签到后，余额展示和热力图是否能即时刷新。
