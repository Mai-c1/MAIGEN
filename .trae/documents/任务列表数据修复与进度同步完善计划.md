## 任务模块重构与仪表盘功能完善计划

针对您提出的反馈，我将对任务模块进行深度重构，解决字段映射失效和状态同步不及时的问题，并补全仪表盘统计接口。

### **1. 实体类全局驼峰化重构**
我们将把 `com.maigen.api.entity` 包下的所有实体类字段从下划线命名（snake_case）统一重构为 Java 标准的驼峰命名（camelCase），以彻底解决 MyBatis-Plus 在开启 `map-underscore-to-camel-case` 后的映射失效问题。

- **重构对象**: 包括 `Task`、`User`、`PointsRecord`、`GeneratedData`、`CommunityContent` 等所有核心实体。
- **映射保障**: 保留 `@TableField(value = "snake_case")` 注解，确保与现有数据库表结构无缝对接。
- **Mapper 同步**: 更新 `src/main/resources/mapper/*.xml` 中的 `BaseResultMap`，将 `property` 属性名同步修改为驼峰。
- **代码适配**: 全局搜索并替换 Service、Controller 及 Consumer 中对 Getter/Setter 的调用。

### **2. 任务状态同步机制优化**
完善 `TaskStatusConsumer` 的逻辑，确保任务执行进度能够实时、可靠地反馈到前端列表：
- **顺序调整**: 收到状态更新消息后，**优先更新数据库** (`taskService.updateById`)，确保数据持久化。
- **缓存同步**: 数据库更新成功后，再更新 Redis 缓存。
- **进度持久化**: 确保 AI 流水线的中间进度（如 10%, 50% 等）也能在数据库中体现，从而让任务列表能够正确渲染。

### **3. 仪表盘统计 API 开发**
目前系统确实缺少针对任务状态分布的统计接口。我将补全这一功能：
- **接口路径**: `GET /task/statistics`
- **功能描述**: 返回当前登录用户的任务概览，包括：
    - **进行中**: 处于“分析中、生成中、验证中”状态的任务总数。
    - **已完成**: 状态为“已完成”的任务总数。
    - **已失败**: 状态为“生成失败、超时”的任务总数。
- **技术实现**: 
    - 新建 `TaskStatisticsVO` 模型。
    - 在 `TaskService` 中实现基于当前用户 ID 的分类统计逻辑。

### **预期效果**
- 任务列表 `/task/list` 将能正常显示创建/更新时间。
- 任务进度将实时在列表页展示，不再停留在“待处理”状态。
- 前端仪表盘将获得可靠的数据支撑，展示用户的任务执行概况。
