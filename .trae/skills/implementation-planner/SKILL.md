# 实施规划器

本技能指导编写代码前的规划阶段。它确保需求明确，考虑最佳实践，并获得用户对方案的批准。

## 工作流程

1.  **分析请求**: 理解用户想要构建什么。
2.  **制定选项**:
    -   确定 2-3 种实施方案（例如：不同的库、模式或架构选择）。
    -   强调“最佳实践”建议。
    -   如有必要，简要解释优缺点。
3.  **起草实施步骤**:
    -   列出计划采取的顺序步骤（例如：“创建文件 X”、“添加方法 Y”、“更新配置 Z”）。
4.  **咨询用户**:
    -   使用 `AskUserQuestion` 工具。
    -   展示选项（通常使用 `multiSelect: false`）。
    -   在问题描述或单独的确认问题中列出步骤。
    -   **等待**用户的回复。
5.  **继续**:
    -   一旦用户选择了一个选项并确认，就在*下一轮*中使用 `Write` 或 `SearchReplace` 工具继续。

## 示例用法

如果用户问“添加文件上传功能”：

1.  **调用技能**: `implementation-planner`
2.  **技能动作**:
    -   检查首选 `minio` 还是 `local` 存储。
    -   建议创建 `FileController` 和 `FileService`。
    -   问：“存储后端：本地 vs MinIO？”和“最大文件大小限制？”。
3.  **用户回复**: "MinIO, 10MB"。
4.  **技能动作**: 继续实现支持 MinIO 的 `FileController`。

## 指导原则

-   **主动**: 不要只问“你想要什么？”。提供*解决方案*供选择。
-   **循序渐进**: 清晰的计划可以防止混乱。
-   **最佳实践**: 始终主张将最稳健、最可维护的解决方案作为默认推荐选项。
