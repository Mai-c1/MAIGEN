# 一致性审查清单

在实现功能后，请仔细检查此清单以确保数据完整性。

## 1. 数据库一致性 (@Transactional)
- **检查**: 该方法是否涉及多个 DB 写操作 (INSERT/UPDATE/DELETE)？
- **行动**: 如果是，请在 Service 方法上添加 `@Transactional(rollbackFor = Exception.class)`。
- **验证**: 确保异常没有在方法内部被捕获并吞掉（或者重新抛出它们）。

## 2. 缓存一致性
- **检查**: 此操作是否更新了已缓存的数据（例如：用户信息、任务状态）？
- **行动**:
    - **更新**: 先更新 DB，然后删除/更新 Redis key。
    - **删除**: 先删除 DB，然后删除 Redis key。
    - **读取**: Cache Aside 模式 (读 Redis -> 未命中 -> 读 DB -> 写 Redis)。
- **验证**: TTL 设置是否合理？

## 3. MQ 可靠性
- **检查**: 是否发送了 MQ 消息？
- **行动**: 确保 MQ 消息在本地事务提交*之后*发送（如果需要严格一致性），或者接受最终一致性。
